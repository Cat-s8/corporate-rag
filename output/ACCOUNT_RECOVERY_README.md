# Архив восстановления материалов ВКР

Дата сборки: 13 ноября 2026 года.

## Назначение

Этот архив сохраняет материалы, необходимые для продолжения ВКР после утраты доступа к аккаунту или истории чата. В него сознательно не включены модели, рабочая база SQLite, сессионные ключи, пароли, локальные PDF-документы организации и резервные копии: они могут содержать чувствительные данные, имеют большой размер либо не нужны для восстановления текстовой и программной части диплома.

## Текущая тема и цель

Тема: «Разработка системы интеллектуального поиска по документации организации на основе технологии RAG с разграничением доступа пользователей (на примере УФК по Свердловской области)».

Цель: разработать и экспериментально оценить локальный прототип поиска и формирования ответов по документации, предоставляющий сведения в соответствии с полномочиями пользователя.

## Состояние пояснительной записки

- В `documents/Диплом_Котов.docx` находятся введение и первая глава.
- В первой главе сформулированы четыре задачи, модель угроз, требования Ф1–Ф7, Б1–Б16 и критерии К1–К5.
- В `documents/Глава_модель_угроз_RAG_Котов.docx` находится расширенная замена подраздела 1.3. Она включает активы, нарушителей, границы доверия, 11 угроз У1–У11, матрицу угроз и связь угроз с мерами и проверками.
- Вторая глава должна описывать только фактическую реализацию: проектирование, индексацию, гибридный поиск, интерфейс и безопасность, экспериментальную оценку, ограничения.

## Фактическая реализация прототипа

- Python; единый веб-интерфейс Flask/Jinja.
- Лексический поиск BM25, векторный поиск FAISS `IndexFlatIP`, объединение Reciprocal Rank Fusion с `RRF_K = 60`.
- Эмбеддинги `intfloat/multilingual-e5-small`, размерность 384.
- Локальная Qwen3-8B-Q4_K_M через `llama-cpp-python`.
- SQLite: пользователи, роли, ACL, документы, фрагменты, векторы, история, аудит.
- Пять ролей: обычный пользователь, бухгалтер, специалист по отчётности, администратор, специалист по ИБ.
- Для неадминистратора документ доступен, только если роль входит в ACL и уровень документа не превышает допуск роли.
- ACL-фильтрация выполняется до BM25, FAISS, формирования контекста и вызова Qwen.
- Администратор входит в два этапа: пароль и одноразовый локальный код.

## Ключевые файлы кода

- `source-code/app/rag_service.py` — авторизованный поиск и генерация.
- `source-code/app/search_hybrid.py` — BM25, FAISS и RRF.
- `source-code/app/chat_hybrid.py` — контекст и Qwen.
- `source-code/rag_roles/security.py` — роли, ACL и политика доступа.
- `source-code/rag_roles/server.py` — Flask-маршруты, сессии, CSRF, интерфейс, аудит.
- `source-code/rag_roles/storage.py` — SQLite и подготовка разрешённого корпуса.
- `source-code/rag_roles/tests/` — автоматические проверки доступа и RAG-интеграции.

## Что требуется перед защитой

1. Подготовить фиксированный тестовый набор вопросов, эталонных фрагментов и прав доступа.
2. Сравнить BM25, FAISS и гибридный поиск по Recall@k, MRR и времени поиска.
3. Оценить ответы по полноте условий, подтверждённости и корректности ссылок.
4. Выполнить положительные и отрицательные проверки доступа.
5. Не заявлять как доказанные промышленную эксплуатацию, абсолютную защиту от prompt injection, нагрузочную устойчивость, резервное восстановление и сетевую автономность, пока не проведены отдельные испытания.

## Восстановление рабочего контекста

1. Распаковать архив в безопасное локальное место.
2. Открыть `documents/Диплом_Котов.docx`, `documents/Глава_модель_угроз_RAG_Котов.docx` и этот файл.
3. Передать новому помощнику тему, цель, четыре задачи, этот README и нужные документы.
4. Для продолжения разработки использовать `source-code/README.md` и `source-code/CODEX_CONTEXT.md`.

## Не включено намеренно

Модели GGUF, рабочий каталог `rag_roles/data`, PDF-корпус, `.venv`, `.archive`, журналы сервера и любые секреты. Их нужно хранить отдельно в защищённом месте.
