# Ролевой сервер существующего RAG

Модуль интегрирован с `app/search_hybrid.py` и `app/chat_hybrid.py`.
Адаптер `backend.py` выполняет настоящий BM25 / FAISS / RRF и вызов Qwen.
Единственный светлый интерфейс Flask обслуживает поиск и управление в одном сеансе.

Полные команды запуска, правила доступа, публикация и восстановление описаны
в [корневом README](../README.md). Используйте корневое `.venv` и `start.ps1`.
Прежнее окружение модуля сохранено в `.archive/cleanup-2026-09-24/legacy-environment.zip`.

| Роль | Доступ |
|---|---|
| RAG_USER | Поиск разрешённых general, личная история |
| RAG_ACCOUNTANT | Бухгалтер: поиск, фильтры и чтение разрешённых документов |
| RAG_REPORTING_SPECIALIST | Специалист по отчётности: поиск, фильтры и чтение разрешённых документов |
| RAG_ADMIN | Все документы, пользователи, ACL, настройки, загрузка, публикация и удаление |
| RAG_SECURITY_AUDITOR | Разрешённые документы и поиск, аудит, события, CSV; без изменений |

Пустой или неверный ACL запрещает доступ неадминистратору.
`/api/session` выдаёт сведения только о текущем сеансе и разрешённых документах.
`/api/search` требует сеанс и CSRF; `/api/history` возвращает только личные вопросы.
Прямые URL управления проверяются на сервере независимо от меню.

SQLite, PDF загрузок, история и ключ сеанса находятся в `data/` и исключены из Git.
Документы после удаления из базы не участвуют в поиске; исходные PDF сохраняются.
Экспорт аудита ограничен 2000 строками и экранирует формулы CSV, как в прототипе.

Повторный импорт исходного корпуса безопасен при неизменных исходных файлах:

```powershell
cd C:\corporate-rag
.\.venv\Scripts\python.exe -B rag_roles\import_existing.py
```

Импорт не переопределяет существующие ACL и не восстанавливает удалённые документы.
Изменённый ранее импортированный корпус требует отдельной миграции версии.
Исходная документация прототипа сохранена в `.archive/integration-2026-09-23/`.
