# Corporate RAG

Единое светлое веб-приложение: поиск и ответы Qwen, история, документы,
пользователи, настройки и аудит. Все разделы используют одну сессию и один адрес.

## Вход пользователя и администратора

Обычные пользователи входят по логину и паролю на `/login`. Администратор выбирает
«Вход администратора» или открывает `/admin/login`. После пароля на `/admin/verify`
нужно ввести одноразовый код. До его подтверждения документы, PDF, поиск и все
защищённые HTML-страницы и API недоступны. Через обычную форму `/login` войти
администратором нельзя.

На основном компьютере откройте PowerShell и создайте код для своего логина:

```powershell
cd C:\corporate-rag
.\.venv\Scripts\python.exe -B .\rag_roles\admin_access.py generate --login admin
```

Замените `admin` на логин нужного администратора. Команда выводит код один раз и
срок в UTC. Код содержит 16 случайных символов (80 бит), допускает ввод с дефисами
или пробелами и в любом регистре. Он действует **600 секунд с момента генерации**;
на границе срока уже недействителен. Новый код отменяет прежние неиспользованные
коды этого администратора. В базе сохраняется только SHA-256 хеш случайного кода.
Веб-маршрута генерации нет. Не перенаправляйте вывод команды в журнал или файл.

Для другого каталога данных установите одинаковое значение `RAG_ROLES_DATA` в
окружении сервера и в PowerShell, где запускаете утилиту. По умолчанию используется
`C:\corporate-rag\rag_roles\data`. Утилита не создаёт новую пустую базу вместо
отсутствующей рабочей. Первую учётную запись по-прежнему создаёт локальная команда
`.\.venv\Scripts\python.exe -B .\rag_roles\server.py --init-admin`.

Ожидание второго этапа отдельно ограничено десятью минутами после пароля. Если
истёк только код, создайте новый. Если закрылась попытка входа — сначала снова
введите логин и пароль. «Отменить вход» закрывает текущую попытку на сервере.
Пять ошибочных кодов закрывают попытку. Дополнительно допускается не более
10 проверок за скользящие 600 секунд **на учётную запись**; новая cookie, другой IP,
новый код, повторный первый этап и перезапуск сервера не сбрасывают этот лимит.
После блокировки подождите до 10 минут, затем начните вход заново и создайте код.

Успешный вход не ограничен сроком кода: новый код каждые десять минут не требуется.
Действует выход после бездействия: 5 минут у администратора, 15 минут у остальных.
Пассивные проверки состояния в браузере не продлевают сеанс. Выход, смена и сброс
пароля отзывают сессии; изменения роли, активности, пароля и `session_version`
также отменяют незавершённые входы и неиспользованные коды. Повышение роли до
администратора требует нового полного входа. Назначение этой роли через веб-формы
остаётся запрещено. Существующие администраторы сохраняют свою роль.

Временный пароль администратора не заменяет код. После обоих этапов он получает
доступ только к обязательной смене пароля, затем входит заново с новым кодом.

### Обновление существующей установки

Перезапустите приложение через `STOP.cmd`, затем `START.cmd` (для удалённого
режима используйте прежний `start-remote.ps1`). До первого обновления заполненной
базы SQLite автоматически создаётся согласованная копия в
`rag_roles/data/backups/roles-before-admin-2fa-*.sqlite3`, включая данные WAL;
при `RAG_ROLES_DATA` — в `backups` выбранного каталога. Ошибка резервного копирования
останавливает миграцию. Копия содержит конфиденциальные данные и требует тех же
ограничений доступа, что рабочая база. Для отката остановите сервер и восстановите
согласованную версию кода и базы.

Первое включение механизма отзывает прежние административные сессии. Повторные
запуски этого не делают. Пользователи, хеши паролей, документы, ACL, векторы и
история сохраняются. Копии, созданные до этого обновления, не содержат новых
журналов и изменений, сделанных после него. Обновите сервер перед запуском новой
утилиты кодов: старая версия сервера не должна работать с новой схемой входа.

### Права Windows и независимость второго фактора

Локальная команда **не доказывает физическое присутствие**: её можно запустить
через RDP, PowerShell Remoting или другой доступ к ОС. Независимость второго
фактора обеспечивается отдельно защищённым доступом к основному компьютеру,
а не наличием двух веб-форм. Если пароль сайта и доступ к ПК доступны одному
нарушителю, такая схема не даёт независимого второго фактора.

В Windows ограничьте доступ к каталогу проекта, Python-окружению, базе,
`session.key`, резервным копиям и локальному запуску доверенными операторами и
учётной записью службы. Обычным пользователям сайта не выдавайте доступ к файлам
проекта или удалённой командной строке основного ПК. Защитите вход Windows и
удалённый доступ отдельными учётными данными; оставляйте экран заблокированным.
Запрет только на файл `admin_access.py` недостаточен при доступе к базе или коду.
Права ОС и конфигурацию Tailscale приложение автоматически не меняет.

Генерация, отмена, ошибки и подтверждение кода попадают в аудит без секретов.
Локальные операции имеют пустой IP, веб-события — IP запроса или сессии.
Произвольный `X-Forwarded-For` не считается достоверным: доверие включается явно
только для существующего локального прокси. Лимит кодов работает по учётной записи.

## Восстановление пароля

Пользователь обращается к администратору. В разделе «Пользователи» администратор
раскрывает «Сбросить пароль», подтверждает действие и нажимает «Выдать временный
пароль». Пароль показывается только в ответе на этот запрос; передайте его
пользователю по согласованному защищённому каналу. Он действует 30 минут.
При входе пользователь обязан задать постоянный пароль от 12 до 256 символов.
До смены пароля остальные страницы и API недоступны. После смены нужно войти заново.
Повторный сброс отменяет предыдущий временный пароль. Отключённым пользователям
пароль не выдаётся. Сброс собственного пароля через административную кнопку запрещён.

Обычная смена пароля доступна по ссылке «Сменить пароль» под именем пользователя
и требует текущий пароль. Сброс и смена отзывают прежние сеансы. В базе хранятся
только хеши, в аудит записываются события `password_reset` и `password_changed`
без паролей. Существующие пароли и роли при обновлении не изменяются.

## Группы документов

Администратор создаёт группу на странице «Документы» через «Создать группу
документов». В колонке «Группа» выберите назначение — перенос сохранится автоматически.
«Без группы» убирает документ из группы. Каждый документ находится в одной группе
или без группы. Перенос не меняет его ACL, состояние или индекс.

Группа выбирается также в форме поиска и фильтрах списка документов. В поиске
можно выбрать все группы, одну группу или документы без группы. Для обычных
пользователей показываются только группы с доступными опубликованными документами.
Фильтрация по группе и правам выполняется до BM25, FAISS и вызова Qwen.
API `/api/search` принимает дополнительное поле `group`: ID группы, `ungrouped`
или пустую строку. Создавать группы и перемещать документы может только администратор.

## Быстрый запуск

Доступ к документу настраивается одним списком «Кому доступен документ» при
загрузке и в карточке документа. Администратор имеет доступ всегда; без отметок
документ доступен только ему. Уровень назначается автоматически при сохранении.
Для старых документов форма показывает фактически разрешённые роли, а их права
не меняются до сохранения. В таблице документов перечислены роли с доступом.

**Запуск двойным щелчком:** откройте `START.cmd` в корне проекта.
Он запустит сервер в фоне, дождётся прогрева моделей и откроет браузер.
Повторный запуск открывает уже работающий интерфейс. Окно запуска можно закрыть
после открытия браузера; сервер продолжит работать. Логи —
`rag_roles/data/server.out.log` и `rag_roles/data/server.err.log`.
Для кнопки на рабочем столе создайте ярлык на `START.cmd` средствами Windows.

**Выключение двойным щелчком:** откройте `STOP.cmd`. Он останавливает сервер
этого проекта, в том числе во время прогрева моделей. Повторное выключение
безопасно. Для включения снова используйте `START.cmd`.

В результатах поиска нажмите «Открыть отрывок в PDF»: в новой вкладке появятся
текст фрагмента и изображение соответствующей страницы оригинала. Кнопка
«Открыть оригинальный PDF» открывает полный документ на физической странице PDF.
Номер страницы PDF может отличаться от напечатанного номера. Доступ проверяется
при каждом открытии страницы и файла. Если оригинал отсутствует, остаётся доступен
сохранённый текст с пояснением. Переиндексация для этой функции не требуется.

```powershell
cd C:\corporate-rag
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Открыть **http://127.0.0.1:8502**. Окно запуска должно оставаться открытым;
Ctrl+C останавливает сервер, запущенный из этого окна. Если сервер уже работает,
запускатель показывает адрес без запуска дубликата. Ошибки видны в окне сервера.
Для локального запуска используется корневой `start.ps1`, для удалённого — `start-remote.ps1`.

Используется корневое `.venv` с рабочими BM25, FAISS, E5 и llama-cpp-python.
Прямой запуск: `.\.venv\Scripts\python.exe -B rag_roles\server.py`.

Модели загружаются и прогреваются перед открытием сервера: дождитесь строки
`Open http://127.0.0.1:8502`. Это убирает загрузку моделей из первого запроса.
Отключение предварительной загрузки: `$env:RAG_PRELOAD = '0'`.
На RX 5700 XT используется установленная сборка Vulkan и `RAG_GPU_LAYERS=-1`
по умолчанию; значение `0` принудительно включает CPU. Flash Attention оставлен
выключенным: на этой видеокарте проверенные запросы с ним выполнялись медленнее.
Время ответа зависит от длины контекста и ответа; 6 секунд не являются гарантией.

## Доступ с ноутбука через интернет

Безопасный рекомендуемый вариант — закрытая сеть Tailscale. Приложение продолжает
слушать только `127.0.0.1`, а Tailscale выдаёт приватный HTTPS-адрес. Порт 8502 на
роутере открывать не нужно.

1. Установите Tailscale на вычислительный компьютер и ноутбук и войдите на обоих
   устройствах в одну учётную запись.
2. На вычислительном компьютере запустите PowerShell, при необходимости от имени
   администратора, и выполните:

```powershell
cd C:\corporate-rag
powershell -ExecutionPolicy Bypass -File .\start-remote.ps1
```

3. Скрипт напечатает адрес вида `https://имя-компьютера.имя-сети.ts.net`.
   Откройте его на ноутбуке. Оба устройства должны быть подключены к Tailscale,
   а окно RAG-сервера на вычислительном компьютере должно оставаться открытым.

Удалённый доступ действует только пока открыто это окно. `Ctrl+C` останавливает
публикацию и локальный RAG-сервер.

Не используйте проброс TCP-порта 8502 на роутере и не применяйте Tailscale Funnel:
в приложении находятся внутренние документы, а публичный доступ в его модель угроз
не входит. Подробности и диагностика приведены в [REMOTE_ACCESS.md](REMOTE_ACCESS.md).

## Работа

Войдите существующей учётной записью. Пароли и права при объединении интерфейсов
не менялись. Раздел «Поиск» выполняет настоящий BM25 + FAISS + RRF, затем Qwen
формирует ответ с документом и страницей. «История» содержит личные вопросы.

Администратор назначает уровень и ACL через «Документы» → выбранный документ,
создаёт пользователей и меняет настройки. Администратор загружает текстовые PDF и
публикует их через «Индексация». Аудитор читает журнал и выгружает CSV.

После первоначального импорта 4 PDF и 378 фрагментов были доступны только
администратору. Фактические уровни и разрешённые роли назначает администратор.
Не делайте служебные документы общими ради демонстрации — используйте тестовые PDF.

## Структура и защита

Подробная карта каталогов, модулей, маршрутов, таблиц БД и потока запроса:
[PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md).

- `rag_roles/server.py` — единый Flask/Waitress-сервер и маршруты.
- `rag_roles/templates/`, `static/` — светлый интерфейс.
- `rag_roles/security.py`, `storage.py` — роли, ACL, метаданные и версия корпуса.
- `app/rag_service.py` — поиск только по разрешённым опубликованным чанкам.
- `app/search_hybrid.py`, `chat_hybrid.py` — BM25/FAISS/RRF и промпт Qwen.
- `rag_roles/ingestion.py`, `import_existing.py` — загрузка и импорт документов.
- `rag_roles/data/` — SQLite, PDF, ключ сеанса; вне Git.
- `data/`, `index/`, `models/` — сохранённые документы, индексы и локальные модели.
- `.archive/` — резервные копии и отключённый Streamlit; вне Git.

ACL проверяется до BM25/FAISS и формирования контекста. Для неадминистратора
одновременно нужны разрешение роли в ACL и достаточный допуск. Общего кэша
ответов нет. Изменение прав во время запроса отменяет выдачу устаревшего ответа.
В БД сохраняются только вопросы, не ответы. Генерации Qwen выполняются последовательно.

Публикация проверяет эмбеддинги и атомарно сохраняет их со статусом в SQLite.
Исходные JSON/FAISS не перезаписываются. Удаление документа исключает его из поиска;
сохранённые PDF физически не удаляются.

## Модели

По умолчанию — локальная Qwen3-8B, контекст 4096, 6 потоков. E5 загружается только
из локального кэша. CUDA не требуется. Скорость зависит от сборки и оборудования.
Пример конфигурации CPU с сохранённой моделью 3B:

```powershell
$env:RAG_MODEL_PATH = 'models/qwen2.5-3b-instruct-q4_k_m.gguf'
$env:RAG_GPU_LAYERS = '0'
$env:RAG_THREADS = '4'
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

После изменения конфигурации сервер нужно перезапустить. Качество 3B на ноутбуке
нужно проверить отдельно. Менять embedding-модель без пересчёта векторов нельзя.

## Действующие роли

| Роль | Права |
|---|---|
| Администратор | Все документы, пользователи, ACL, загрузка, публикация и удаление |
| Специалист по ИБ | Журнал, события, CSV; чтение разрешённых документов, без изменений |
| Бухгалтер | Поиск, фильтры и чтение документов, разрешённых бухгалтеру |
| Специалист по отчётности | Поиск, фильтры и чтение документов, разрешённых специалисту по отчётности |
| Обычный пользователь | Поиск по разрешённым общим документам и личная история |

Пользователи видят личную историю; администратор также видит историю всех
пользователей через «Пользователи» → «История запросов пользователей», включая
удалённых (до 500 последних записей, с фильтром по учётной записи).
Удаление закрывает доступ и сохраняет историю; логин остаётся зарезервированным.
Бухгалтер и специалист по отчётности
имеют допуск до restricted, но доступ к каждому документу обязательно требует ACL.
У одного пользователя одна роль; документ можно разрешить нескольким ролям.

Коды новых бизнес-ролей: `RAG_ACCOUNTANT` и `RAG_REPORTING_SPECIALIST`.
Прежние роли перенесены один к одному в пользователях и ACL: расширенный пользователь
→ бухгалтер, оператор базы знаний → специалист по отчётности. Права изменения
документов остались только у администратора. Пустые ACL остались пустыми.
Администратор должен проверить соответствие ACL фактическому назначению документов.
