# Удалённый доступ к Corporate RAG

## Рекомендуемая схема

```text
Ноутбук
  │ HTTPS, зашифрованная закрытая сеть Tailscale
  ▼
Tailscale Serve на вычислительном компьютере
  │ HTTP только внутри этого компьютера
  ▼
Waitress / Flask: http://127.0.0.1:8502
  │
  ├── SQLite и документы
  ├── BM25 + FAISS
  └── локальная Qwen
```

Вычисления, модели, индексы и документы остаются на основном компьютере. Ноутбук
показывает веб-интерфейс и отправляет вопросы. Скорость генерации определяется
вычислительным компьютером; через сеть передаются только HTTP-запросы и ответы.

Tailscale Serve предоставляет приватный HTTPS-адрес только устройствам закрытой
Tailscale-сети. Сам RAG-сервер остаётся на `localhost`, поэтому не становится
доступным всей локальной сети или публичному интернету.

## Что потребуется

- вычислительный компьютер включён и не находится в спящем режиме;
- на обоих компьютерах установлен Tailscale;
- оба устройства подключены к одной Tailscale-сети;
- на вычислительном компьютере работают Tailscale и RAG-сервер;
- пользователь знает логин и пароль именно от Corporate RAG.

Tailscale даёт сетевой доступ, но не отменяет авторизацию приложения. Роли, ACL,
сессии, CSRF и журнал аудита продолжают действовать как обычно.

## Первый запуск

### 1. Подготовить Tailscale

На вычислительном компьютере и ноутбуке:

1. Установить Tailscale для Windows.
2. Войти в одну учётную запись или добавить ноутбук в разрешённую tailnet.
3. Убедиться, что оба устройства отображаются как подключённые.

На текущем вычислительном компьютере Tailscale уже установлен. Если команда
`tailscale` отвечает `Access is denied`, откройте PowerShell от имени администратора.

### 2. Запустить RAG и приватный HTTPS-прокси

На вычислительном компьютере:

```powershell
cd C:\corporate-rag
powershell -ExecutionPolicy Bypass -File .\start-remote.ps1
```

При первом вызове Tailscale Serve может показать ссылку подтверждения включения
HTTPS для закрытой сети. Откройте её и подтвердите действие. После настройки в
PowerShell появится адрес примерно такого вида:

```text
https://desktop-name.example.ts.net
```

Не закрывайте окно удалённого запуска. Нажатие `Ctrl+C` останавливает и приватную
публикацию Tailscale Serve, и запущенный этим скриптом RAG-сервер.

### 3. Открыть сайт на ноутбуке

1. Подключить Tailscale на ноутбуке.
2. Открыть напечатанный `https://...ts.net` адрес в браузере.
3. Войти под учётной записью Corporate RAG.

Обычный пользователь входит на `/login`. Администратор на том же HTTPS-адресе
открывает `/admin/login`, вводит пароль, затем код на `/admin/verify`.
Код создаётся **на основном компьютере**, в PowerShell:

```powershell
cd C:\corporate-rag
.\.venv\Scripts\python.exe -B .\rag_roles\admin_access.py generate --login admin
```

Замените логин при необходимости; каталог `RAG_ROLES_DATA` должен совпадать с
каталогом сервера. Введите показанный код на ноутбуке в течение 600 секунд.
Он используется один раз. Новый код отменяет предыдущий. Если истекло ожидание
после пароля, начните вход заново. Пять ошибок закрывают попытку; общий лимит
10 проверок за 600 секунд сохраняется при очистке cookie и смене IP.

Команду может выполнить и оператор с удалённым доступом к Windows. Она не
подтверждает физическое присутствие. Ограничьте доступ к ОС, базе, ключу сессии,
копиям и файлам проекта отдельными правами Windows. Доступ к веб-сайту через
Tailscale сам по себе не должен давать доступ к командной строке ПК. Подробные
ограничения схемы и действия после сброса пароля описаны в README.
Конфигурация Tailscale для двухэтапного входа не изменяется.

## Последующие запуски

Команда остаётся той же:

```powershell
powershell -ExecutionPolicy Bypass -File C:\corporate-rag\start-remote.ps1
```

Скрипт заново запускает сервер, показывает адрес и включает проксирование только на
время своей работы. Если RAG уже запущен обычным способом, скрипт попросит сначала
остановить его, чтобы включить защищённые cookie сессии.

## Остановка удалённого доступа

Нажмите `Ctrl+C` в окне `start-remote.ps1`. Скрипт остановит публикацию и дочерний
процесс RAG. Если ранее вручную использовался фоновый режим Tailscale Serve, убрать
его можно командой `tailscale serve off` в PowerShell от имени администратора.

## Проверка и диагностика

### Сайт не открывается на ноутбуке

На вычислительном компьютере проверить локальный сервер:

```powershell
Invoke-RestMethod http://127.0.0.1:8502/api/session
```

Ожидается JSON с полями `csrf` и `user`. Затем проверить Tailscale:

```powershell
tailscale status
tailscale serve status
```

Вторая команда должна показывать HTTPS-адрес и прокси на
`http://127.0.0.1:8502`.

### Адрес открывается, но вход постоянно сбрасывается

Удалённый режим запускает сервер с `RAG_HTTPS=1`, поэтому cookie сессии работает
только через HTTPS. Открывайте адрес `https://...ts.net`, а не локальный адрес
`http://127.0.0.1:8502`.

Если сервер ранее был запущен обычным `start.ps1`, остановите его через `Ctrl+C` и
запустите заново через `start-remote.ps1`.

### Компьютер засыпает

В параметрах электропитания Windows запретите сон вычислительного компьютера на
время удалённой работы. Выключенный или спящий компьютер не сможет выполнять поиск
и генерацию.

## Доступ в одной локальной сети без Tailscale

Технически Waitress можно привязать к `0.0.0.0` и открыть порт в Windows Firewall,
но текущий проект использует обычный HTTP между браузером и сервером. Для внутренних
документов этот вариант менее безопасен, поэтому он намеренно не включён по
умолчанию. Даже в одной Wi-Fi-сети рекомендуется использовать Tailscale Serve.

## Чего делать не следует

- Не пробрасывать порт `8502` на домашнем или офисном роутере.
- Не выставлять Waitress напрямую в публичный интернет.
- Не использовать `tailscale funnel`: Funnel делает сервис публичным.
- Не отключать вход, CSRF, ACL или Secure cookie ради упрощения подключения.
- Не копировать модели, БД и внутренние PDF на ноутбук: для удалённой работы это
  не требуется.
